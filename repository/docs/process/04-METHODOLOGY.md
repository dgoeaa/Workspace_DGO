**Purpose.** Describe how the inventory was built, so a reader can repeat it and get the same answer.

## The method is a program, not a reading

This package is generated. `scripts/process-discovery.mjs` reads the artifacts listed in document 3
and writes `docs/reference/process-inventory.json`; `scripts/process-docs.mjs` renders these documents
from that file. Running `npm run process:discover` on a clean checkout reproduces the inventory byte
for byte, and `node scripts/process-discovery.mjs --check` fails the build if the committed inventory
has drifted from what the sources now say.

The consequence worth stating plainly: no sentence in the catalogues was written about a specific
process by hand. Where a statement is wrong, either the artifact it cites is wrong or the extractor
misread it. Both are findable and fixable; neither is a matter of opinion.

## How each kind of artifact was read

| Artifact | Method | What it can establish | What it cannot |
| --- | --- | --- | --- |
| Power Automate export | The action graph is walked depth-first. Each action becomes a step: its type, its run-after conditions, the variables and trigger fields its expressions read, its connector, and the actions that name it as a predecessor. | Every step, every branch, every connector call, every recovery path. | What the workflow is for, who owns it, how critical it is. An export states none of the three. |
| Designer paste package | Same walk, over the pasted scope. | The designed action graph. | Whether the design is what runs. |
| Workspace module | Call sites are matched for governed writes, operator confirmations, backend calls, outcome messages and navigation handoffs. | Every governed write and its declared governance. | The presentation between writes, which is deliberately not modelled as process. |
| Configuration | Frozen declarations are parsed directly. | Rules, roles, routes, states, transitions, retention and service levels as declared. | Whether a declaration is enforced anywhere but where it is read. |
| Run record | Outcome and response status are read. | That the endpoint executed and what it returned. | Availability, latency, or that a business transaction completed. |

## The rule applied when evidence ran out

Where this standard asks for a field and no artifact carries it, the field is left empty and the
absence is raised in the gap register with the authoritative source needed to fill it. It is never
filled with a plausible default. That is why several catalogues below repeatedly read "Not evidenced":
each of those is a real hole in the supplied material, recorded rather than papered over.
