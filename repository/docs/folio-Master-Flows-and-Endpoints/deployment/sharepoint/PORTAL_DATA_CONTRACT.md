**Version 1.0.0 · AUTHORITATIVE**

The data the portal sends, the data it reads back, and where each field must be persisted. This is the specification flows conform to — not a description of what any flow currently does. A flow that does not satisfy it is wrong; the contract is not adjusted to match a flow.

> **Precedence.** Where this disagrees with a deployed flow, the flow is wrong. Where it disagrees with the functional documentation, the disagreement is a defect in one of them and is recorded rather than resolved silently.

## Conventions

- **required** — Required means the portal always sends it, or the portal cannot function without reading it back. Not a SharePoint column constraint.
- **persistence** — list/column names a provisioned target. `null` means the contract requires the value but no provisioned column holds it — a gap, reported by scripts/verify-portal-data-contract.mjs.
- **timestamps** — Every *AtUtc column is ISO 8601 with a Z suffix. The portal sends ISO strings; flows must not reformat them.
- **reference** — referenceId is minted by the flow, never by the portal. The portal's localId is a client-generated correlation id and is not a reference.

## Cross-cutting

- **rateLimit** — Every endpoint reads, updates and creates a bucket in Portal Rate Limits keyed `<ENDPOINT>_IP:<X-Forwarded-For>`. 60-minute fixed window. See D8 for the per-endpoint limits.
- **telemetry** — Every endpoint writes one row to Portal Flow Telemetry inside its capture scope, never on the request path.
- **envelope** — Every response is the standard envelope, and the HTTP status is the envelope's own status code. A branch that sets a failure code must have that code survive to the response.
- **cors** — Access-Control-Allow-Origin must name the real portal origin. It is currently the literal `https://your-host` on every endpoint.
- **filenamePolicy** — The Universal Filename Policy is applied by the UPLOAD flow, not the client. document-portal/ performs no filename normalisation.
