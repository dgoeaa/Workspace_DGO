# DGO_ENDPOINT_INVENTORY — the flow that asks the tenant

`folio-Master-Flows-and-Endpoints/inventory/DGO_ENDPOINT_INVENTORY.designer-paste.json`, generated by
`scripts/build-inventory-flow.mjs`, asserted by `tests/inventory-flow.test.mjs`.

```bash
npm run build:inventoryflow   # regenerate the package from its sources
npm run test:inventoryflow    # 27 assertions, each named for a defect that was present
```

---

## Why it exists

Every other artefact here states what the estate **should** be.
`docs/folio-Master-Flows-and-Endpoints/registers/endpoint-register.json` says which workflow each contract key addresses,
`npm run reconcile` derives `endpoint-workflow-ids.json` from it, `config/endpoint-atlas.data.js`
renders it, and the Endpoint Console judges a configured URL against it. All of that compares two
things this repository holds. None of it asks Power Automate.

This flow asks Power Automate. For each candidate flow GUID it calls **GetFlow**,
**ListFlowOwners** and **ListCallbackUrl**, and records what came back. That settles the class of
condition the console names but cannot reach:

| Condition | Visible today? |
|---|---|
| The workflow id is right and the flow behind it was **deleted** | No |
| The flow exists but is **turned off** | No |
| The flow was **renamed** away from the name every document uses | No |
| The flow's only **owner has left** the agency | No |
| The manual trigger answers a **different method** than the contract expects | No |
| Two candidate GUIDs exist for one workflow and **only one is live** | No |

Twenty-six registry records across twenty application workflows; twenty-three carry an evidenced
flow GUID and three do not.

## Where the registry comes from

The scope's first action is a Compose holding the registry. It is **generated**, not typed:

```
docs/folio-Master-Flows-and-Endpoints/registers/endpoint-workflow-ids.json ──┐
   the authority — contract keys, workflow  ├─→ scripts/build-inventory-flow.mjs
   ids, categories, methods, flow names.    │        │
   Derived from the tenant register by      │        └─→ DGO_ENDPOINT_INVENTORY.designer-paste.json
   `npm run reconcile`.                     │
                                            │
docs/folio-Master-Flows-and-Endpoints/registers/inventory-flow-candidates.json
   the only facts the authority lacks — the tenant flow GUIDs, their exported
   names, and what each pairing rests on.
```

Hand-maintained, that array restates twenty-six records of contract keys, workflow ids, categories
and methods from the register — the exact shape of thing this programme has watched drift four
times. `npm run test:inventoryflow` fails if the committed package differs from a rebuild, so the
registry inside the flow cannot disagree with the register that governs the estate.

**The join was checked against the original before it replaced it.** The generated registry
reproduces the twenty-six hand-written records field for field, so nothing was lost in making it
derivable.

## The two outputs, and only one of them may leave

`ListCallbackUrl` returns a **signed** trigger URL. That is a bearer credential: possession alone
authorizes invoking the flow. This repository's entire secret posture exists because twenty-five of
them were once published in a committed archive.

| | `Compose_Restricted_Extraction_Result` | `Compose_Redacted_Governance_Result` |
|---|---|---|
| Signed callback URLs | **Yes** — every one retrieved | No |
| Callback URL, `sig` removed | Yes | Yes — `sig=<CREDENTIAL_REMOVED>` |
| Signature length | Yes | Yes — 43, or a short number meaning a truncated paste |
| Complete flow definitions | Yes | No |
| Connection references | Yes | No |
| Owner records (names, addresses, object ids) | Yes | Count only |
| Raw connector action results | Yes | No |
| Flow state, timestamps, trigger, method | Yes | Yes |
| **Where it goes** | **Run history only** | Attached to the report mail |

The restricted tier is complete and unredacted exactly as specified, and it goes nowhere. Anyone
who can open a run of this flow can read twenty-three signed trigger URLs — which is a fact about
who should be able to open a run of this flow, and is worth deciding deliberately rather than
inheriting.

The governance tier carries every retrieved field except the signature. Reporting the signature's
**length** rather than its value is the same reasoning `core/endpoint-atlas.js` applies: a Power
Automate signature is base64url of an HMAC-SHA256 — 32 bytes, 43 characters unpadded, with no
legitimate variation. The length is the whole diagnostic value without being a credential.

`tests/inventory-flow.test.mjs` asserts this on the serialised package, not field by field,
because "no credential leaves this flow" is a property of the whole string.

The package this replaces was a scope copied out of the designer. Nine defects, in the order they
would have been discovered:

| 2 | Six fields spelled `body('Get_Flow_Definition')?['body']?[…]` | `GetFlow`'s response body **is** the flow object, so this addresses a property the connector does not return. | 3 | `Compose_Normalized_Callback_URL` accepted `Skipped` from both lookups but did not depend on `Get_Flow_Definition` succeeding | A failed definition read skips both lookups, the compose runs anyway, and the record is filed as **FOUND with a null identity** — while the enclosing scope, carrying an unhandled failure, also fires `Scope_Handle_Retrieval_Failure` and files the **same record as NOT FOUND**. | 6 | `uniqueApplicationWorkflowCount: 20`, a literal | Correct the day it was typed. It would go on being reported after the register stopped agreeing with it | `length(union(body('Select_Application_Workflow_Ids'), json('[]')))` — `union` with an empty array is the distinct of an array |

**Nothing was removed from the restricted tier.** The author's `informationPolicy` for it — no
filtering, reduction, redaction, masking, validation or omission — is intact and asserted. What
changed is which of the two tiers reaches the mail action.

**One item is a decision, not a defect.** The report goes to `dgsRegistry@nitda.gov.ng`, the
address the original package named. The governance tier carries no credential, but it does list
flow GUIDs, owner counts and endpoint availability for the whole estate. If that should go to a
narrower distribution, change the `emailMessage/To` parameter in
`scripts/build-inventory-flow.mjs` and rebuild.

`shared_office365` is declared in the envelope and bound by no action in this scope. It was in the
original and is left in place: removing a connection reference from a package that is pasted into
a flow this repository cannot see is a change with a blast radius and no benefit.

## Before pasting

Power Automate accepts **Initialize variable** only at the top level of a workflow, so the six
variables the scope reads cannot travel inside it. `DGO_ENDPOINT_INVENTORY.variables.md` lists
them, and `DGO_ENDPOINT_INVENTORY.variables.designer-paste.json` carries them as a package.

`EnvironmentName` is the one that matters: it is the environment the Flow Management connector
reads, and an empty value is handled rather than assumed away — the scope files every record as
not processed and records `ENVIRONMENT_NAME_REQUIRED`, instead of calling the connector with
nothing and reporting twenty-six failures that all mean the same thing.

The connection this flow needs is **Power Automate Management**, and it must be a connection whose
identity can read the flows being inventoried. A flow the connection owner cannot see returns a
retrieval failure, which the run reports as such — it is not silently absent.

## What this flow still does not tell you

Stated so nobody assumes otherwise.

- **It does not confirm a candidate pairing is the right one.** Where a workflow has two candidate
  GUIDs, the run reports what each one is; deciding which serves the contract key is a judgement
  made against what it reports.
- **It does not revoke anything.** Reading a signed callback URL does not rotate it. Rotation is
  `docs/folio-Master-Flows-and-Endpoints/cutover/FLOW_DECOMMISSION_INVENTORY.md`.
- **It does not write its findings anywhere durable.** The run history holds them and the mail
  carries a copy. Filing the governance tier into a list, and diffing it run over run, is the
  obvious next step and is not built.
- **It has not been run against the tenant.** Every assertion here is about the definition. What
  the tenant returns is the point of running it, and this repository has never had that answer.
