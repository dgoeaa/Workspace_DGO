# Endpoint provisioning register

> Generated by `scripts/build-provisioning-reference.mjs` — do not edit by hand.
> Every row is read from a package or a register in this repository; each section names
> which one.

An endpoint on either platform is one HTTP-triggered Power Automate flow, invoked
directly by the browser at its signed trigger URL. `config/endpoints.config.js` states
the arrangement in the tree itself: *"Every URL below is invoked directly by the
browser. There is no proxy, broker or other intermediary in the request path… The flow
behind each URL is therefore the only place authentication, authorisation and
validation can be enforced — it must enforce them itself."* What each flow does enforce
is in section 4 and on its own page.

**No trigger URL appears anywhere in this reference.** A signed URL is a bearer
credential; the workflow id it addresses is not, and is what is recorded.
